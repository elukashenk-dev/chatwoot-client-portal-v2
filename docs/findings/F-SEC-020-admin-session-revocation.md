# F-SEC-020: Active portal-admin sessions ignore Chatwoot revocation

- status: open
- found_in: SEC-DEEP-001 targeted two-auditor disposition; `DEEP-R1-F03` on historical commit `a61b4975ae7b59e244c0b5bbc4efd02466aa075c` and reassessment commit `0c25c7575221ed19b21390abb8a5f1e364f2e06f`
- risk: medium
- urgency: Fix before the next release or feature slice that relies on tenant-admin authority or offboarding.
- area: Tenant-admin session authorization lifecycle
- confidence: high
- evidence: `backend/src/modules/tenant-admin/adminAuthService.ts:59-80`; `backend/src/modules/tenant-admin/adminAuthRepository.ts:399-420`; `backend/src/modules/tenant-admin/adminSessionGuard.ts:19-47`; `backend/src/modules/tenant-admin/adminVerification.ts:54-68,77-157`; both independent reports under `docs/superpowers/audits/2026-07-13-full-application-risk-audit/follow-ups/sec-deep-001-two-auditor/`
- failure_path: A principal receives a valid 12-hour portal-admin session while eligible in Chatwoot, then is demoted, disabled, removed or otherwise made ineligible. Current-session resolution continues to trust only the tenant-scoped token hash, expiry and stored administrator snapshot, so the stale cookie still reaches protected branding, legal-document and Telegram bridge operations until logout or expiry.
- counterevidence: The session is tenant-bound, signed/hashed, explicitly revocable by logout and limited to 12 hours. Live Chatwoot eligibility is checked before the login challenge, and F-SEC-003 separately requires a recheck immediately before session creation. Those controls do not revoke an already-created session after a later upstream authority change.
- load_impact: A naive live Chatwoot role lookup on every protected admin request would add synchronous external I/O to the admin hot path, multiply calls across tabs and create availability coupling. The fix must use a documented bounded freshness window or generation/revocation signal, coalesce concurrent refreshes and avoid per-request writes or upstream calls.
- fix_short: Add bounded, fail-closed current-eligibility freshness for active portal-admin sessions. Revalidate or consume a trusted revocation/version signal at a documented interval, revoke all affected portal sessions on a negative result, and coalesce concurrent refreshes without calling Chatwoot on every request.
- acceptance: A session created for an eligible administrator is denied protected reads and mutations after the upstream test double revokes confirmation, account membership or administrator role and the documented freshness boundary is reached. Negative results revoke the relevant tenant-admin sessions. Concurrent checks inside the freshness window perform bounded shared work, ordinary protected requests do not add per-request Chatwoot calls/writes, tenant isolation remains intact, and targeted backend integration/load assertions plus required lint/build/test/review gates pass.
